# Pomopet 时间陪伴与回顾设计

状态：已确认，进入实现  
日期：2026-09-04  
基线版本：0.1.22

## 1. 目标与范围

Pomopet 继续以桌面宠物的情绪陪伴为第一体验，同时补齐轻量时间管理闭环：用户能在主窗口或桌面宠物上查看专注/休息倒计时和进度，暂停、提前完成或停止；系统长期保存实际发生的专注、休息、排除时段、提醒和下班事件，并在主窗口回顾最近七天。

本次不增加复杂项目管理、标签体系、云同步、养成数值或历史编辑。Todo 只用于回答“时间花在哪件事上”。

## 2. 信息架构与界面

- 保留现有主窗口、番茄钟、Todo 和四个设置页签的整体结构。
- 在现有一级页签中增加“时间回顾”，不重做首页。
- 主窗口倒计时下增加细进度条，并保留三个操作：暂停/继续、提前完成/结束休息、停止。
- 桌面宠物保持 300px 左右宽度。控制区为两排：第一排显示阶段、任务摘要、倒计时和细进度条，第二排显示三个紧凑按钮。
- 正常陪伴时显示倒计时与进度；气泡出现时桌面控制区暂时隐藏，气泡结束后恢复。主窗口计时始终可见。
- 主窗口与桌面宠物只渲染同一份 runtime 状态，任何一侧操作后另一侧立即同步。

## 3. 计时状态机

### 3.1 状态

- `idle/focus`：待开始。
- `stopped/focus`：刚刚停止；交互上等同待开始，用于给用户明确反馈，下一次 start 可进入运行。
- `running/focus`：专注中。
- `paused/focus`：专注暂停。
- `running/break`：休息中。
- `paused/break`：休息暂停。
- `idle/focus + pendingBreakChoice`：休息结束，等待选择下一步。

### 3.2 操作

- 暂停只冻结当前阶段；继续从原剩余时间恢复。
- 专注自然结束或点击“提前完成”都完成本轮，按实际分钟入账、Todo 完成番茄数加一、播放庆祝，然后自动进入休息。
- 休息自然结束或点击“结束休息”都进入下一步选择，不自动开始专注；该操作在 running 和 paused break 均有效。
- 下一步为：继续当前任务、选择下一个未完成 Todo、暂时停止。当前 Todo 已完成或不存在时不能继续它。
- “停止”结束整轮，不庆祝、不进入休息、不增加完成番茄数，但保存已经产生的实际专注或休息明细。休息中的停止直接进入 stopped，不产生下一步选择；等待选择时的“暂时停止”清除 pending choice 并回到 idle。
- Todo 完成与本轮专注完成相互独立，Todo 只由用户勾选完成。
- 自定义专注和休息时长是计算倒计时、进度和历史计划时长的唯一基准，不允许回退到固定 25/5。
- 同一结束、停止或下一步命令重复到达时，第一次生效，后续按当前状态无操作返回，不能重复记账或报错打断 UI。

## 4. 工作时间与下班规则

用户配置工作日、上班时间、计划下班提醒时间、最晚下班时间和多个固定排除时段。最晚下班默认 22:30，计划提醒时间与最晚时间相互独立。旧数据迁移时上班时间默认 10:00、最晚下班时间默认 22:30。

计划下班时间到达后始终出现宠物提醒；`blockMode` 开启时宠物变大遮挡屏幕，关闭时只显示桌面气泡。用户可“收工了”或“再工作 N 分钟”，N 使用现有可配置 `snoozeMinutes`；每次延长都产生新的提醒。到达最晚下班时间后不再允许延长。最终下班时间取用户点击收工的时间；未提前收工则取最晚下班时间。

工作规则只保存当前配置，不保存每日规则快照。固定排除时段会被物化为当天的时间明细。排除时段与真实专注重叠时保留原始专注记录，但从有效专注统计中裁掉，并标记为“休息时段工作”。

## 5. 历史存储

### 5.1 文件组织与一致性

配置、当前运行状态和历史统一保存在 `pomopet-state.json`，通过现有临时文件加原子替换一次提交。第一版不拆分第二个物理文件，避免计时器、Todo 累计和历史在进程退出时只写入一部分。历史在 JSON 内按本地日期分区，长期保存，界面默认只处理和展示最近七天：

```json
{
  "analytics": {
    "schemaVersion": 1,
    "days": {
      "2026-09-04": {
        "date": "2026-09-04",
        "rangeStartAt": 1788477600000,
        "intervals": [],
        "reminderOccurrences": [],
        "workdayEvents": []
      }
    },
    "appliedEventIds": []
  }
}
```

所有命令和 tick 通过 runtime 串行队列执行。同一原子提交同时包含 timer、Todo 和 analytics；`appliedEventIds` 让完成事件、提醒事件和恢复事件可以幂等重放，重复命令不能产生重复完成、重复提醒或重复累计。

### 5.2 时间段明细

```json
{
  "id": "focus-1788487200000-ab12cd",
  "cycleId": "focus-1788487200000-ab12cd",
  "kind": "focus",
  "todoId": "todo-001",
  "taskTitle": "完成时间回顾方案",
  "label": null,
  "plannedMs": 1500000,
  "startedAt": 1788487200000,
  "endedAt": 1788488700000,
  "segments": [
    { "startedAt": 1788487200000, "endedAt": 1788487800000 },
    { "startedAt": 1788487920000, "endedAt": 1788488700000 }
  ],
  "status": "completed",
  "completionReason": "natural"
}
```

`kind` 为 `focus`、`break` 或 `excluded`。`status` 为 `running`、`paused`、`split`、`completed` 或 `stopped`。完成原因是 `natural`、`early`、`stopped` 或排除时段的 `scheduled`。实际时长只由已闭合 `segments` 求和；暂停时间由总跨度减去实际片段得到。标题使用开始时快照，Todo 改名或删除不改变历史。停止的专注计入 Todo 的 `spentMs`，但不增加 `completedPomos`；无 Todo 或已删除 Todo 仍保留历史标题，不更新 Todo。

运行中的时间段在开始时建立，暂停时闭合当前 segment，继续时新增 segment，完成或停止时闭合并终结。跨午夜记录按本地零点切成每天独立 fragment，ID 为 `<sessionId>:<day>:<kind>`，保持同一 `cycleId`。零点前 fragment 的 `endedAt` 为本地次日零点、`status` 为 `split`、`completionReason` 为空；只有最后一个 fragment 保存终态和完成原因。查询时 `split` 只贡献时长，不贡献完成/停止次数。番茄完成、提前完成和停止次数按 `cycleId` 去重，时长按 fragment 求和。由于所有日期分区在同一次原子写入中提交，不存在只写入半个跨日记录。

恢复规则：未到期 running 状态继续运行；已到期 focus 只完成一次并回到 idle，不补开已经过时的休息；已到期 break 进入 pendingBreakChoice；paused 状态保持暂停。升级前的 paused 状态缺少暂停时间点，不伪造升级前时间线。其已知投入量 `plannedMs - remainingMs` 保存在终结日 fragment 的 `unplacedActiveMs`，计入 Todo 实际用时和任务分布，但不绘制到具体时间轴，也不做排除时段裁剪；回顾中单列为“升级前未定位时间”。恢复后第一次继续才建立可定位 segment。升级后直接提前完成或停止都使用该已知投入量，不生成零时长假片段。超过庆祝宽限期的 focus 仍记账但不播放迟到庆祝。

### 5.3 提醒明细

```json
{
  "occurrenceId": "alarm-001:1788479400000",
  "alarmId": "alarm-001",
  "reminderText": "起来喝水",
  "scheduledAt": 1788479400000,
  "firedAt": 1788479401200,
  "muted": false,
  "response": {
    "type": "dismissed",
    "respondedAt": 1788479410000,
    "snoozeMinutes": null
  },
  "parentOccurrenceId": null
}
```

`firedAt` 表示 runtime 成功认领到期 occurrence 的时间，即使宠物气泡排队或只成功发送系统通知也算触发。`response.type` 可为 `dismissed`、`snoozed`、`timed_out` 或 `expired`；应用退出时仍为空，重新启动后超过展示宽限期标记 `expired`。所有响应命令必须携带来源 `occurrenceId`，只有从 `response: null` 开始的第一次响应生效；重复点击或冲突响应无操作返回。提醒统计按用户配置的 `reminderText` 精确合并，不按动作枚举，也不使用每次变化的 AI 台词；`alarmId` 仅用于明细定位同名闹钟。修改提醒文本不回写历史。稍后提醒生成新 occurrence，并通过 `parentOccurrenceId` 关联来源。

### 5.4 工作日事件

`workdayEvents` 记录 `offwork_snoozed`、`offwork_finished` 和 `latest_offwork_limit`，包含发生时间、延长分钟、收尾句及来源 occurrence。实际开始工作时间取当天第一条专注明细，最终下班时间取 `offwork_finished` 或 `latest_offwork_limit`。现有动作、`blockMode`、可配置稍后分钟和忽略升级均保留；新增 `latestTime`，要求计划提醒时间早于最晚时间。一次延长若跨过最晚时间，只延长到最晚时间；最晚时间触发后不再显示延长按钮。应用在最晚时间后恢复时只补记一次 limit 事件并结束当天提醒。下班 snooze/finish 也必须携带 occurrenceId，第一次响应生效，双击或重放不能产生第二条事件。

固定排除时段要求同一天内开始早于结束，重叠区间先合并。当天产生第一条计时、提醒或下班事件时，写入当天的 `rangeStartAt`，并按当时配置物化当天排除区间；这两个字段属于当天已经形成的时间分布边界，不是完整规则快照。当天后续修改只影响尚未开始的区间，已经开始或结束的区间不回写。应用整天未运行且没有任何记录时不凭空创建历史日。

## 6. 时间回顾计算

- 实际专注时间：当天全部 focus segments 和 `unplacedActiveMs` 的总和，再裁掉与 excluded 重叠的部分。
- 任务分布：按 `todoId` 汇总实际专注分钟，缺少 Todo 的记录归入“未关联任务”。
- 专注/休息/排除分布：时间轴统计范围从当天首次事件时写入的 `rangeStartAt` 开始，到最终下班时间结束；今天尚未下班时到当前时间。上班前或收工后的专注仍计入任务耗时，但单独标记“计划外工作”。状态分布使用互斥优先级 `excluded > focus > break > 未记录`，同一墙上时间只能计入一种状态，不会双计。
- 提醒累计：按 `reminderText` 统计 occurrence 数；时间点分布按 `firedAt` 的半小时桶统计。
- 暂停、提前完成、停止：按 segments 和 completionReason 计算，跨日次数按 cycleId 去重。
- 实际下班和延长次数：按 workdayEvents 计算。
- 所有汇总只在查询时生成，不持久化第二份累计数据。

## 7. 兼容与迁移

- 保留现有 `pomopet-state.json`、Todo 累计番茄数和累计 `spentMs`。
- 升级前没有开始/结束时间的累计数据不能伪造成时间轴；详细回顾从新版本启用后开始。
- 当前正在运行或暂停的旧计时器升级后可继续；首次产生下一次状态转换时建立历史记录，并避免重复完成。
- 原子状态写入失败时命令返回失败且不向 UI 宣称保存成功；内存状态保留并在下一次串行操作重试，同一 event ID 不能重复影响 Todo 或历史。启动遇到损坏 JSON 时先把原文件移动为带时间戳的 `.corrupt` 副本，再回退默认状态，不能直接覆盖原文件后假装成功。

## 8. 验收与回归

自动化测试覆盖：全部状态转换；运行中和暂停中的自然/提前/停止；结束休息与停止休息的区别；pending choice 的继续、切换和停止；实际分钟与 Todo 分开累计；自定义时长；跨午夜 fragment、split 状态与 cycle 去重；排除合并和重叠裁剪；提醒认领、超时、稍后、文本聚合、双击和冲突响应；重复计时命令和双窗口并发串行；精确包含今天在内的最近七天；旧状态迁移及 paused 状态直接完成/停止；运行/暂停/过期 focus 与 break 恢复；缺失和损坏历史及 corrupt 备份；开放 segment 的当日预览；本地日期和 DST；原子保存失败后的幂等重试；下班配置校验、延期裁剪、双击响应、忽略、最晚时间和恢复补记。

当日回顾包含运行中的开放 segment 时，界面只在内存中用 segment 起点到当前时间计算预览，并按本地零点和 excluded 裁剪；不把临时 `endedAt` 写回存储。

现有回归重点：Todo 启动与计数、提醒调度与去重、静音、AI/TTS 不阻塞气泡、宠物召回、编辑草稿保护、下班重复提醒和睡眠恢复。

桌面人工验收覆盖：主窗口与宠物同步、宠物尺寸和按钮可点性、两排布局、长任务名截断、倒计时与气泡互斥、进度条在暂停时冻结、下班遮挡和 Apple Silicon 安装启动。
